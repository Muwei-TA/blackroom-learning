# BlackRoom 学习打卡开发规格（离线开发版）

用户已批准前一轮设计，并要求核查后开发，禁止直接推送上线。本目录是新建的隔离本地 Git 仓库，不绑定任何远程。

## 首发闭环
一个配置的学习分区、一个由运营自行发布的公共 Flag 话题。成员在 /learning 表单创建目标，服务端以当前成员身份通过 NewPostManager 提交 Flag 回复。打卡表单创建正常 Discourse 话题；每次提交有服务端持久化的 receipt 和请求去重键。无关键词猜测、无自动替他人发布、无管理员/系统身份代发。

目标所需学习日 N=1..366；开始日期不得回溯；结束日期含首尾，窗口最长 366 天且 N<=窗口。第一版单个进行中/待审核目标；目标建立后时间不可暗改，允许主动结束但保留历史。统一 Asia/Shanghai 自然日（当前日期范围 UTC+08:00），客户端不能指定打卡日期。

每日有效天数按目标+自然日去重。仅本人、关联、已发布、未隐藏/删除、普通话题首帖、仍在原分区/原话题的记录有效。Flag 必须已公开给本分区成员；被拒绝或隐藏的目标不能绕过审核展示。审核按 receipt.submitted_at 归属日期，不按审批日。目标关闭后不得新提交，审批后仍可追溯原始有效日期。

进度 min(C,N)/N；当前/最高真实连胜；每日用户级 XP=10，同日多个来源不能重复奖励；100 XP 一级，从 Lv.1 起。首次、连续7天、累计30天、完成目标的学习成就。审核失效和恢复重新计算，奖励使用追加式正负流水而非篡改历史。冻结卡/学习币/商店/排行榜竞争/提醒不在本版本。

## 安全与架构
默认 enabled=false、category_id=0、flag_topic_id=0。安装不创建分区或帖子、不启用配置、不发送运营消息。Rails engine + 原生 Ember 页面/话题入口；纯 Ruby 领域规则 + PostgreSQL 持久化适配。读写均需要登录和 Guardian 检查；所有展示按访问者的权限过滤，不能通过用户摘要泄露受限分区记录。禁止缓存跨用户的完整 JSON。

写请求采用当前会话 CSRF 防护、RateLimiter、服务器强参数、用户行锁和事务。提交和奖励均可重试；后台任务只核对状态，不自动发布。计划字段冻结，不提供客户端修改 submitted_at/status/XP 的接口。无核心代码补丁，无外部服务运行时依赖。

## 核验边界
连接仓库 Muwei-TA/discourse 固定参考提交 6318da11adede54e9e5b2bbbeef8a79c2157503c，版本文件 2026.10.0-latest；不是线上版本证明。当前容器 Ruby 3.3.8 / Node 22.16.0，未提供 Rails、PostgreSQL、Redis/完整 Discourse，DNS 下载尝试失败。离线规则测试、语法和包检查应实际运行；原生 RSpec/Ember/实际并发与审核集成测试必须明确标为尚未执行。交付属于待集成验证的开发包，不能描述为生产可安装即用。
