# 本地自审记录

范围：`0.1.0-dev` 的规则、业务适配、界面源码和文档。没有可调用的独立评审代理，因此本记录是开发者自审，不能替代独立安全评审或真实系统测试。

## 已修复

1. 缺少目标字段时 Ruby 关键字参数异常可产生500：参数默认为nil，并由规则返回明确业务错误；新增失败回归后验证通过。
2. 新版原生路由模板使用 `@controller.model`，不是 `@model`：实际读取固定版本官方插件模板，增加源码契约测试并修正。
3. 日历辅助函数输出 `complete`，初始文案只有 `done`：检查实际函数输出、修正文案和契约期望，避免已打卡日期出现翻译缺失。
4. 生成请求UUID在 try 之外，异常时表单可能停留在busy状态：移到受catch/finally保护的范围；添加回归契约检查。
5. 跨日审核不能使用获批帖的创建日：独立回执保存服务器提交时间；审核关联恢复使用原话题编号，防止移动记录后继续计分。
6. 普通帖不应绕过审核：全部通过 NewPostManager；表单传真实输入时长，不通过管理员身份或关闭审核实现打卡。
7. 既有原生徽章可能是管理员手动授予：只撤销本插件登记且ID匹配的UserBadge；不占有已有徽章，不允许奖励授予网站权限。
8. 页面不能直接展示未做权限过滤的缓存总数：先过滤当前源帖可见性再计算卡片和摘要；统计响应禁止共享缓存。

9. 旧目标完成后删帖可能重开、与新目标同时活跃：新增完成封存时间，达标或开启后续目标时在用户锁内写入。新增5项生命周期测试先观察2项失败再通过；对应宿主请求用例仍待执行。

## 保留的限制与集成风险

- Rails加载、迁移、真正SQL并发、Ember/GJS编译与浏览器交互尚未跑通；列为发布阻断，不以源码测试代替。
- Flag 插槽在普通话题模板已核对，嵌套视图需额外验证；旧 Flag 回复保留直接进度链接。
- 最近20个“我的目标”、分页目标广场、最近50篇记录的显示上限明确；汇总需要读取成员历史源记录，成员长期高频使用后须压测并评估分页投影/索引优化。
- 改换配置分区/Flag会影响历史查询范围；没有在线迁移界面，不应在有活跃目标时修改。
- 原生徽章可见性比学习页面更广，撤销是异步行为；默认关闭桥接，权限变更前必须专门验收和处理已有徽章。
- 第一版不允许编辑已提交目标，也没有图片上传控件、冻结卡、学习币或排行榜。这里不存在已做但未展示的实现。

核查以实际源码和离线测试为限；未做渗透测试、负载测试或生产兼容认证。
