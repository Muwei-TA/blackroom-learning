# 学习提交的数据库回滚恢复

恢复修复基于插件提交 `ba78683e55a43a5f9a05476eec82569447f309c3`，验证宿主为 Discourse `6318da11adede54e9e5b2bbbeef8a79c2157503c`、PostgreSQL 18。

正常发帖在学习提交的外层事务提交前就写入 Redis 正文去重键。如果进程此时中断，数据库中的帖子、话题和回执回滚，而 Redis 仍指向不存在的帖子，原样立即重试被正常去重验证拒绝。

插件只为学习请求中匹配服务端用户和原始参数的 PostCreator 实例记录来源。实际规范化正文的核心缓存键和请求原始输入摘要分别保存，连同请求 UUID、请求摘要、用户、类别、帖子 ID、顶层事务 ID 和随机 generation 一起写入。核心键和来源标记在同一 Redis Lua 操作中写入，使用原有有效期和当前站点命名空间；普通发帖行为保持核心实现。

重试仍持有用户事务锁，在进入 NewPostManager 前检查自己的来源标记。仅在用户、请求和原始内容完全一致，PostgreSQL 明确返回原事务 `aborted`，且 `Post.unscoped` 中也不存在该帖子时，才比较并删除旧缓存。Lua 同时比较原始标记字节和核心键的帖子 ID，保护并发替换。已提交、进行中、不可确定、过期状态和异常来源均不清理。状态查询使用保存点隔离查询错误。没有关闭去重、缩短有效期或清空全站缓存。

本修复不能恢复部署前已留下但没有来源标记的旧键；此类键继续按核心正常有效期过期。已完成的同编号重试仍使用原回执，不再次发帖或发奖励。

新增宿主集成测试位于 `spec/requests/recovery_spec.rb`，使用真实 PostgreSQL 顶层事务回滚和 Redis；需宿主测试依赖。离线 `scripts/verify.sh` 不执行这些集成测试。验收报告保留失败基线、测试环境配置和真实进程中断证据。修复没有生产部署或远端推送。

## 浏览器网络中断恢复

固定宿主 Ajax 默认 `ignoreUnsent: true`。网络错误将 `xhr.readyState` 变为 0 时，宿主会忽略错误，Promise 不完成；学习表单的 `catch/finally` 因而不能执行，按钮持续禁用。真实浏览器已复现服务器201提交后丢失响应，以及目标提交的同类问题。

学习目标、打卡、刷新、分页、结束目标、Flag 面板和初次路由加载的 Ajax 显式使用 `ignoreUnsent: false`，让网络错误进入原有异常处理并解除 busy。提交失败时保留原内容和请求 UUID，用户主动原样重试；不自动重复发帖，不改变服务器幂等、限流、审核或Redis有效期。组件销毁后的既有防护保持生效。

真实浏览器回归 `test/browser/network_recovery.cjs` 只用于已经明确批准的隔离实例和纯合成账号，不由离线脚本自动运行。设置 `QA_BASE_URL`（标准安全上下文，例如同测试网络命名空间的 `http://localhost`）、`QA_FIXTURE`（受限读取的合成夹具JSON，含users数组和临时password）、`QA_OUTPUT`（私有测试输出目录）；`NODE_PATH` 指向已经安装的Playwright模块，必要时指定 `QA_BROWSER_BINARY`。不要绕过TLS证书或把不安全域名标记为安全。

该回归使用真实登录和页面表单，通过浏览器故意丢失已提交响应或中断未发送的请求，验证错误可见、按钮和字段恢复、内容/UUID保留、同一目标/帖子的重试、刷新和结束目标恢复，以及一天仅一份XP。测试会创建/结束合成目标并发出合成学习话题；需要支持中文的测试站点、已授权合成账号和足够的普通论坛发帖配额。其他完整页面流程还应独立执行，分页达到阈值后的按钮操作不由这份短回归覆盖。
